# pi-tools-mcp

A local MCP server exposing Pi's built-in coding tools directly to ChatGPT Web. ChatGPT is the only agent: this project does not run the Pi CLI, Pi RPC, or a second model.

## Requirements

- Node.js >= 22.19.0
- OpenAI Secure MCP Tunnel ID and runtime key with Tunnels Read + Use permission
- ChatGPT account/workspace permission to add a custom MCP app

## Install and run

```bash
npm install
npm run build
npm start
```

Startup asks for `WORKSPACE_ROOT`, `CONTROL_PLANE_TUNNEL_ID`, and `CONTROL_PLANE_API_KEY`. Environment values take precedence; the API key prompt is hidden. For local diagnostics without OpenAI:

```bash
npm start -- --local-only
```

The endpoint is printed as `http://127.0.0.1:<port>/mcp`. It binds only to loopback. Press Ctrl+C for graceful shutdown.

## Environment

| Variable                  | Purpose                                           |
| ------------------------- | ------------------------------------------------- |
| `WORKSPACE_ROOT`          | Existing directory used as Pi's working directory |
| `CONTROL_PLANE_TUNNEL_ID` | OpenAI tunnel ID; required unless local-only      |
| `CONTROL_PLANE_API_KEY`   | Runtime key; required unless local-only           |
| `PI_TOOLS_MCP_CACHE_DIR`  | Cache root; defaults to `~/.cache/pi-tools-mcp`   |

Export the variables or run `node --env-file=.env dist/index.js`. `.env.example` contains variable names only. Never commit `.env` or credentials.

## Tools and permission model

| Tool         | Behavior                                                                  |
| ------------ | ------------------------------------------------------------------------- |
| `read`       | Text/images, offset/limit, Pi truncation                                  |
| `bash`       | Arbitrary shell commands, timeout, merged output, exit code and wall time |
| `edit`       | Exact unique replacement using `edits: [{oldText, newText}]`              |
| `write`      | Create/overwrite files                                                    |
| `grep`       | Content search using Pi's ripgrep integration                             |
| `find`       | Glob search using Pi's fd integration                                     |
| `ls`         | Directory listing                                                         |
| `powershell` | Additionally exposed on Windows                                           |

All tools use the pinned `@earendil-works/pi-coding-agent@1.1.0` factories directly. The MCP adapter preserves content/images and errors; Pi primitive structured results are wrapped in `{result: ...}` because MCP requires an object. Object outputs such as `bash` remain objects. Pi details are available in `_meta["pi-tools-mcp/details"]`. Progress-capable MCP clients receive shell updates when they provide a progress token.

Read-only annotations apply to `read`, `grep`, `find`, and `ls`; write/destructive annotations apply to the other tools. ChatGPT controls its own approvals and rendering.

**Full permissions are intentional.** There is no tool allowlist, denylist, path jail, or command sandbox. `WORKSPACE_ROOT` is a working directory, not a security boundary; absolute paths and `..` keep Pi behavior. A caller with `bash` can inspect same-user processes, credentials, and files, including the tunnel process environment. Hiding/redacting the key only prevents accidental logging and persistence; it does not protect it from the coding agent. Use a dedicated low-scope runtime key and revoke it after testing. Only connect trusted clients and treat repo instructions/output as untrusted data.

No separate app authentication is added. Tunnel organization/workspace association is the remote access boundary. Loopback clients on this machine can call the server too.

## OpenAI Secure MCP Tunnel

1. Open [Platform tunnel settings](https://platform.openai.com/settings/organization/tunnels); create/select a tunnel and associate it with the target ChatGPT workspace.
2. Create a runtime API key with Tunnels Read + Use permission. Do not use an admin key.
3. Run `npm start` and enter the workspace, tunnel ID, and key.
4. The app verifies local MCP readiness, downloads/caches the official tunnel client, creates a separate runtime profile containing only an environment reference for the key, and starts the tunnel process.
5. Wait for the printed **tunnel ready** state. In [ChatGPT Plugins](https://chatgpt.com/plugins), choose **Add → Add custom MCP server → Tunnel**. Enter the same ID, choose **No authentication** if available for this intentionally tunnel-only server, review its full permissions, and create the plugin.
6. Start a new chat and select the plugin. Ask it to list files or edit a disposable fixture. Keep `npm start` running for discovery and calls.

Account plan, workspace policy, tunnel associations, and permission restrictions are controlled by OpenAI. Do not bypass them. Tool changes may require **Refresh** in ChatGPT before use.

Reference: [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels), [custom MCP connection](https://developers.openai.com/plugins/deploy/connect-chatgpt).

## Download and cache

Each launch queries the official stable latest [OpenAI tunnel-client release](https://github.com/openai/tunnel-client/releases/latest). The archive is verified against its official `SHA256SUMS.txt` before extracting the executable. Cache hits verify the extracted binary against the saved checksum. This trusts the official GitHub release channel; SHA-256 is not an independent vendor signature.

```text
~/.cache/pi-tools-mcp/tunnel-client/<version>/<platform>-<arch>/
```

`PI_TOOLS_MCP_CACHE_DIR` overrides the root. Runtime profiles are isolated under `<cache>/runtime/` and removed during normal shutdown. Keys are never placed in argv, profiles, or app logs; tunnel logs are redacted. The tunnel receives its runtime key explicitly through an environment reference.

Supported download targets: macOS arm64/amd64, Linux arm64/amd64, Windows amd64. Native Windows execution additionally needs the shells required by the Pi SDK. Native execution is verified on macOS arm64; other platform runtimes require their own smoke verification.

## Verification

```bash
npm run build
npm test
```

The suite exercises actual Pi tools over loopback Streamable HTTP, file writes/edits/searches, protocol errors, process cleanup, streamed redaction, verified download/cache reuse, and checksum rejection. Fake tunnel processes are isolated test fixtures, not production fallbacks.

A real ChatGPT end-to-end test requires a valid runtime key and tunnel ID. Local smoke does not prove remote connectivity.

## Troubleshooting

- **Missing configuration in noninteractive mode:** set all required environment variables; prompts need a TTY.
- **Invalid workspace:** choose an existing directory, not a file.
- **Checksum failure:** the download is refused; retry via the official release channel. Do not bypass checksum verification.
- **Tunnel readiness timeout:** check the redacted diagnostics, key's Tunnels Read + Use permissions, and workspace associations. The app does not claim ready based only on process startup.
- **ChatGPT cannot scan:** keep the app running and choose Tunnel, not the localhost URL. Check OpenAI workspace permissions.
- **Tool metadata changed:** refresh the plugin and start a new chat.
- **Find/grep unavailable:** Pi may need to acquire fd/ripgrep on first use; check outbound networking and Pi's tool cache.
- **Ctrl+C:** the app stops the tunnel and aborts active tools before closing MCP and removing runtime files.
